# 中學生創新比賽：用真實數據寫研究報告

這是教師引導稿，依據本機實驗 `hall-20260922-replay1`（2026-09-22），不是已代學生完成的參賽報告。以下是通用結構；比賽字數、格式及 AI 使用聲明，須另按實際章程處理。本輪資料與回放已獲使用者批准公開；以下本機指令供已有完整環境者重現。

## 1. 題目與可檢驗問題

建議題目：**結合果蠅視覺模型與 3DGS 場景的無人機局部避障模擬**。

研究問題：在相同起點、終點及碰撞代理下，持續更新視覺特徵，是否比固定首幀特徵更容易到達目標？假設可以寫成：「持續更新組的到達率較高。」先寫假設，再看結果；不可把「永不碰撞」當成已證明的結論。

## 2. 用自己的話解釋系統

| 部分 | 本實驗實際作用 |
|---|---|
| 靜態 3D Gaussian Splatting（3DGS） | 產生工廠相機畫面；本輪沒有使用 4DGS |
| Flyvis | 預訓練果蠅視覺迴路，權重凍結；從連續影像提取 72 個特徵 |
| 決策網絡 | 加上目標、速度、上一指令，共 78 個輸入，學習輸出兩個水平速度指令 |
| MuJoCo／Gymnasium 環境 | 模擬 Crazyflie 運動、接觸及每步觀察；高度及偏航固定 |
| 第三身回放 | 顯示已記錄軌跡和姿態，方便分析；觀看一次不等於新增一次實驗 |

本輪是示範學習加 DAgger 嘗試：先跟隨知道代理幾何的示範器收集標籤，再讓學習策略行動、由示範器標註該狀態應採取的指令。測試時沒有示範器控制。這不是全果蠅大腦訓練、自主強化學習或已學會真實距離估計。

## 3. 方法、變量與公平比較

控制場景、權重、20 個測試 seeds、目標判定、物理設定及時間上限；對照只固定首幀的 72 個視覺特徵，其餘目標、速度和上一指令仍更新。每次最多 12 秒，進入目標 0.25 m 範圍算到達。訓練、8 次模型選擇驗證、20 次正式測試使用不同 seeds。

碰撞檢查只涵蓋手動建立的圓柱代理：半徑 0.45 m、高 1.55 m。另用半徑 0.09 m 的保守水平機身包絡計算淨距；這不是 Crazyflie 實際寬度。MuJoCo 接觸與 10 Hz 記錄折線的淨距是兩種不同證據。

## 4. 必須保留的結果，包括退步輪次

| 模型／條件 | 用於擬合的樣本 | 到達 | 代理碰撞 |
|---|---:|---:|---:|
| 原模型，同一驗證組 | 本輪未擬合 | 8/8 | 0/8 |
| 第 0 輪，獲選模型 | 1,600 | 8/8（驗證） | 0/8 |
| 第 1 輪，未選用 | 2,400 | 4/8（驗證） | 1/8 |
| 獲選模型，正常視覺 | 同一第 0 輪權重 | 20/20（正式測試） | 0/20 |
| 獲選模型，固定首幀特徵 | 同一第 0 輪權重 | 0/20（全數逾時） | 0/20 |

共收集 **2,400** 筆，但最後採用的第 0 輪只以 **1,600** 筆擬合。保存的 loss 是兩輪結束值 **0.0090366、0.0318138**，不是完整逐 epoch 曲線；不可連成虛構的收斂曲線。原模型與新模型在相同驗證組都是 8/8，不能宣稱成功率提升。

可引用但須保留限定語的結果段落：

> 在同一工廠局部場景的 20 個保留測試 seeds 中，持續更新視覺特徵的策略達到 20/20 到達，沒有記錄到代理碰撞；平均模擬到達時間為 5.195 秒，所記錄路徑折線的最小水平機身包絡淨距為 0.28695449 m。固定首幀視覺特徵時，20 次均逾時、沒有到達。結果支持持續更新視覺特徵對這個策略的重要性，但未證明真實測距或全場景安全。

## 5. 學生自己完成的分析

1. 由逐次資料重算到達率、平均時間及最小淨距，與摘要核對。
2. 用同一座標尺度畫 20 條路徑，標上障礙和起終點；挑最小淨距一次，看慢播並記錄觀察。
3. 討論為何固定視覺組「零碰撞」仍不算成功，以及第 1 輪收集更多資料仍可能退步。
4. 提出下一個只改一項的實驗，例如擴大起終點範圍；先寫預測與合格標準，再用全新 seeds 測試。

## 6. 證據檔與重現方法

原始資料位於專案的 `outputs/missions/hall-20260922-replay1/`：

- `hall-demonstrations.npz`：`observations` 是 2400×78 特徵，`actions` 是 2400×2 示範標籤；不是完整 RGB 影像集。
- `history.json`、`hall-training.json`：收集、擬合、模型選擇與結果。
- `hall_avoidance-audit.json`、`hall_avoidance-stale-vision.json`：逐次結果及軌跡。
- `run-config.json`、`seed-manifest.json`：參數、種子、程式及來源雜湊。

原始相機影像沒有逐幀完整保存。20 個 seeds 是同一局部場景的變化，不是 20 個真實場景；尚未驗證校園、戶外、降落、多障礙或真機。

現有環境不用重新下載。於專案根目錄開終端，若服務未啟動：

```bash
.venv/bin/python scripts/serve_render_bridge.py --port 8770
```

瀏覽器開 `http://127.0.0.1:8770/bridge` 並保持開啟。在另一終端以**未用過的 run-id 和 seed 區間**重做同類實驗：

```bash
.venv/bin/python scripts/train_hall.py --run-id student-new-run \
  --source-checkpoint checkpoints/missions/hall-20260921-fast/hall-visual-head.pt \
  --seed-base 3000000 --torch-seed 922 --port 8770 \
  --frames 1600 --dagger-frames 800 --rounds 1 --epochs 60 \
  --validation-episodes 8 --audit-episodes 20 --previous-action-dropout 0.5
```

這會產生新結果，不能保證數值完全相同。原輪 seed base 是 2000000。重新研究須保留失敗紀錄，不能反覆看正式測試後挑最佳模型。
